# Contributing

## Build

Rust 1.85 or newer is required.

```console
cargo build
cargo test
```

The development profile uses `opt-level = 1` because the tests encode real
images through libvips. The release profile uses thin LTO and one codegen unit.

The binary needs the engine programs described in [operations](docs/operations.md):
`vips` and `vipsheader`, `jpegtran`, `pngquant` and `ssimulacra2`. They are
discovered from `[engine]`, then `VIPS_BIN`, `JPEGTRAN_BIN`, `PNGQUANT_BIN` and
`SSIMULACRA2_BIN`, then `PATH`. `oxipng` is linked into the binary and needs no
program.

## Tests

- Unit tests live next to the code they test and cover the decision rules, the
  header parsers, the manifest and the replacement logic.
- `tests/pipeline.rs` contains end-to-end tests that use the real encoders. They
  skip themselves when the required binaries are missing, so `cargo test` stays
  green on a bare runner while covering the full pipeline on a machine or
  container that has libvips.
- The integration tests generate their own images with `vips gaussnoise`. There
  are no committed image fixtures.
- When a decision rule changes, change its test in `src/decide.rs` in the same
  commit and explain the new measurement in `docs/measurements.md`.

```console
cargo test
cargo test --test pipeline -- --nocapture
```

## Fixture policy

- Do not commit real photographs, production media or anything derived from a
  customer tree.
- Fixtures must be synthetic: generated by the test at run time, or tiny byte
  sequences built from a parser test.
- Do not commit large binaries. If a bug needs a real-world file, reduce it to a
  minimal synthetic reproduction and describe the bug in the issue.
- Strip metadata from any file you add for a test, and never add a file that
  contains a hostname, path, comment or thumbnail from a real system.

## No infrastructure data in commits

This repository is public. Commits, tests, comments and documentation must not
contain hostnames, IP addresses, domain names (other than `example.com`), user
names, customer or site names, or organisation names.

Use these placeholders:

| Instead of | Use |
| --- | --- |
| a real host | `web-a`, `web-b`, `media-store` |
| a real home or media path | `/home/example`, `/mnt/media` |
| a real domain | `example.com` |
| a real account | `example`, `mediaopt` |

Also excluded: secrets of any kind, tokens, passwords, private keys,
`.env` files, internal URLs, unredacted logs and manifest exports. Reports and
the manifest contain absolute paths and the host name; never paste them into a
commit, issue or pull request.

Run the repository check before you push:

```console
scripts/check-no-secrets.sh
```

If the check flags something, fix the content before pushing. Deleting the file
in a later commit does not remove the data from history, so rewrite the commit
before it leaves your machine.

## Pull requests

- Keep changes focused. A behaviour change, its test and its documentation
  belong in one pull request.
- Add a `CHANGELOG.md` entry for anything user-visible.
- Every measured number in the documentation must come from
  `docs/measurements.md` or from the code's own defaults. If you measure
  something new, add the method and the table there first.
- Run `cargo fmt` and `cargo clippy` before submitting.
- Do not add a dependency that needs the network at run time. The tool has no
  network code and must keep it that way.
